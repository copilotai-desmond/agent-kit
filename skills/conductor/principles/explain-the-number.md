# Explain the number

**When:** Before trusting or reporting a measurement.

**Why:** A number with no cause attached is a guess in costume. Wrong numbers are believed because they look precise.

- Before you report a figure, say what produced it. Name the input, the command and the conditions.
- Ask if the figure is plausible. Estimate it roughly from first principles and compare.
- A surprising result is a bug in the measurement until shown otherwise. Look for caching, a warm start, a wrong target or a changed input.
- Run it more than once. Report the spread, not one run.
- Compare like with like. Same input, same machine, same state, one change between runs.
- Explain a difference by finding its mechanism. If you cannot, say you cannot.
- Report a gain only with the before, the after and the method.

**Example.** A change claims to cut build time by 60 percent. The second run was served from cache. Rerun both cold, then report the real gap.
